# Contributing to rules_coco

## Commits and pull requests

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/), checked by commitizen, for example
`fix(rules): ...` or `feat(rules)!: ...` for a breaking change. Note user-visible changes under `[Unreleased]` in [CHANGELOG.md](CHANGELOG.md).

## Running the checks

Most checks run real popili, so they need a Coco license. Locally, the license already activated on your machine is
used (`local_user`). For a token instead, export `COCOTEC_AUTH_TOKEN` and add
`--@rules_coco//:license_source=local_acquire --repo_env=COCOTEC_AUTH_TOKEN`.

1. Lint (buildifier, prettier, typos, whitespace, links), no license needed but
   [lychee](https://lychee.cli.rs) must be installed (`brew install lychee`):

   ```bash
   pre-commit run --all-files
   ```

2. Starlark unit tests:

   ```bash
   bazel test //coco/private:coco_tests //test/version:version_consistency_test
   ```

3. Integration tests in the root workspace, which generate, verify and compile the packages under `test/`:

   ```bash
   bazel test --config=ci --keep_going --test_output=errors //...
   ```

   `--config=ci` leaves out the `docs` package, so Stardoc's dependencies are not built.

4. End-to-end tests: each directory under [`e2e/`](e2e) is a separate Bazel module that uses rules_coco the way a
   consumer would. Some need `python3 e2e/<dir>/stage.py` first.

   ```bash
   (
     config=bzlmod
     for dir in e2e/*/; do
       # Modules without a WORKSPACE file are bzlmod-only.
       [ "$config" = workspace ] && [ ! -f "$dir/WORKSPACE" ] && continue
       [ -f "$dir/stage.py" ] && python3 "$dir/stage.py"
       (cd "$dir" && bazel test --config="$config" --keep_going --test_output=errors //...) || exit 1
     done
   )
   ```

Set `config=workspace` to run in `WORKSPACE` mode, which needs Bazel 8.3.0 or higher.

## Documentation

- The [README](README.md) is only a front page: what rules_coco is, its requirements and links. Put everything else
  in a guide under [`docs/`](docs/README.md) and link to it from the README's table and from
  [`docs/README.md`](docs/README.md).
- [`docs/reference/`](docs/reference/README.md) is generated by Stardoc from the docstrings in the `.bzl` files. After
  changing a public docstring, regenerate it with `./tools/update_docs.sh`. The script runs Bazel 8.4.2, the version
  CI uses, as newer versions add rows.

  CI fails when the committed reference differs from the generated one.

- [lychee](https://lychee.cli.rs) checks the links in every Markdown file, including `#anchors` into other pages, so
  renaming a heading breaks the links to it. The pre-commit hook runs offline and checks only links between the
  repository's own files; the weekly [Links workflow](.github/workflows/links.yml) also checks external links. Configuration is in [`lychee.toml`](lychee.toml).
